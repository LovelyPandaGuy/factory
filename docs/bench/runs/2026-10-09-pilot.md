## The miss and what changed

**Root cause of the miss:** neither builder nor reviewer looked for the same mistake
elsewhere. The reviewer was told to review changed lines only.

**Rule added (R7, "the same mistake elsewhere"):** name the root cause in one sentence,
then search the codebase for every other place with the same pattern. An unfixed copy that
causes the same wrong behaviour is a finding, proven by a test.

**Re-run:** a fresh reviewer with R7 found the bigint copy, with the same test case the
maintainers wrote (`z.bigint().min(0n).max(23n).check(z.int64())`). It rated it "should
fix" rather than "must fix"; maintainers treated it as part of the fix. Next: the builder
gets the same rule, and the zod task is re-run from a clean snapshot.

## Other lessons

- Docs: one real fix updated user docs. Builders should check whether the behaviour is
  documented and update it.
- Pre-existing failures: zod's typecheck had 15 errors before the change. Builders must
  report the before/after count, as this one did, not claim a clean run.
- Timing tests can fail under parallel load; re-run the single file before calling it a
  regression (the zod builder did this correctly).
